# Awesome Attorneys — "40% At Fault"

Four rendered deliverables and two thumbnails, all built from
`src/` in this project. Nothing here is hand-timed: every hit is
derived from the voice-over.

Generated by `node scripts/write-readme.mjs`.

---

## 1. What each file is

| File | Size | Format | Where it goes |
|---|---|---|---|
| `aa40_9x16.mp4` | 1080×1920, 30 fps, H.264 CRF 16, AAC 320k | full spot with audio | **Reels · TikTok · Shorts** — the primary cut |
| `aa40_16x9.mp4` | 1920×1080, 30 fps, H.264 CRF 16, AAC 320k | full spot with audio | **YouTube · site hero · pre-roll** |
| `aa40_9x16_alpha.mov` | 1080×1920, ProRes 4444, `yuva444p10le` | transparent, **no audio** | drop over B-roll in Premiere / Resolve / Final Cut |
| `aa40_9x16_alpha.webm` | 1080×1920, VP9, `yuva420p`, `alpha_mode=1` | transparent, **no audio** | drop over B-roll in CapCut / browser |
| `aa40_16x9_alpha.mov` | 1920×1080, ProRes 4444, `yuva444p10le` | transparent, **no audio** | as above, landscape |
| `aa40_16x9_alpha.webm` | 1920×1080, VP9, `yuva420p`, `alpha_mode=1` | transparent, **no audio** | as above, landscape |
| `thumb_9x16.png` / `thumb_16x9.png` | end-card still at frame 459 (15.300s) | poster frame | thumbnail / still ad |

**Overlay mode** drops the background, the vignette, the film grain and all
audio, and switches every piece of type to a two-part shadow so it survives
being composited over unknown footage. The horizon *fills* (sun disc, ridge
silhouettes) are kept; the sky gradient behind them is not.

Duration for all four compositions: **16.500s = 495 frames**
(last spoken word at 13.900s plus a 2.6s end-card hold).

## 4. Loudness

Target: **−16 LUFS integrated, true peak ≤ −1 dBTP.**

The voice-over file is never normalised. The single master gain lives in
`src/audio/Soundtrack.tsx` as `VO_GAIN`. Measure with:

```bash
npx remotion ffmpeg -i out/aa40_9x16.mp4 -map 0:a -vn \
  -af loudnorm=I=-16:TP=-1:LRA=11:print_format=json -f null -
```

(Remotion's bundled ffmpeg is built with a small filter whitelist that has
no `ebur128`; `loudnorm` in print mode reports the same measurements.)

Once a music bed is added, re-measure and reset `VO_GAIN` — the current
value was measured against voice alone.

## 5. Re-rendering after a new `vo.mp3`

Drop the new take at `assets-in/vo.mp3`, then:

```bash
node scripts/scan-assets.mjs      # copies assets-in/ -> public/, writes src/assets.ts
node scripts/transcribe.mjs       # whisper.cpp medium.en, word-level timestamps
node scripts/render-all.mjs       # all six videos + both thumbnails
node scripts/write-readme.mjs     # regenerates this file
```

**Nothing else needs editing.** `src/timing/beats.ts` looks every sync point
up by word from `src/timing/vo-words.json`, and the composition duration is
`t.end + 2.6s`, so a longer or shorter read re-times the whole spot
including its length.

### Individual render commands

```bash
# Full, with audio
npx remotion render AA40-9x16 out/aa40_9x16.mp4 --codec=h264 --crf=16 --audio-bitrate=320k
npx remotion render AA40-16x9 out/aa40_16x9.mp4 --codec=h264 --crf=16 --audio-bitrate=320k

# Overlay, alpha, muted
npx remotion render AA40-9x16-overlay out/aa40_9x16_alpha.mov  --codec=prores --prores-profile=4444 --image-format=png --pixel-format=yuva444p10le --muted
npx remotion render AA40-9x16-overlay out/aa40_9x16_alpha.webm --codec=vp9    --pixel-format=yuva420p --image-format=png --muted
npx remotion render AA40-16x9-overlay out/aa40_16x9_alpha.mov  --codec=prores --prores-profile=4444 --image-format=png --pixel-format=yuva444p10le --muted
npx remotion render AA40-16x9-overlay out/aa40_16x9_alpha.webm --codec=vp9    --pixel-format=yuva420p --image-format=png --muted

# Thumbnails
npx remotion still AA40-9x16 out/thumb_9x16.png --frame=459
npx remotion still AA40-16x9 out/thumb_16x9.png --frame=459
```

CRF is passed per-command, never in `remotion.config.ts`: it is an
H.264/VP9 setting and ProRes rejects it outright.

On a headless box, add
`--browser-executable=<path to chrome-headless-shell>`.
